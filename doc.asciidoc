== Background

The need for a simple, lightweight, and portable build system for C projects often arises in environments where users want to minimize external tool dependencies. Existing build systems such as Make, Ninja, or CMake introduce additional files or complexity that might not align with certain project goals, especially in scenarios requiring single-file solutions or constrained environments.

This project originated from a desire to create a compact build system capable of handling most common build tasks without requiring anything beyond a C compiler. Rooted in the philosophy that building a project should rely solely on the compiler itself, this system eliminates the need for additional tools while maintaining flexibility and simplicity.

== Requirements

The single-header build system must meet the following requirements:

=== Must Have
- Autodetection of source files (`.c` and `.cpp`) in user-defined directories.
- Support for multiple executables and libraries within a single project.
- A build configuration structure defined entirely within the single header, without requiring additional files.
- Dependency tracking to decide whether a file or target requires rebuilding, based on:
  * Changes to the source file.
  * User-defined optional dependencies.
- Separate compilation of source files into object files (`.o`) and linking them into the final target (executable/library).
- Support for GCC and Clang compilers.
- A flag for forcing a full rebuild of all files.

=== Should Have
- Ability to specify additional compilation flags per file (e.g., optimization or warning flags).
- Cross-platform compatibility (Linux, macOS, Windows).
- Detection and graceful handling of missing compilers or incorrect build configurations.
- User-defined include directories and library paths.

=== Could Have
- Parallelized builds to speed up compilation when multiple files are involved.
- Verbose and silent build modes for detailed or minimal console output.
- Support for custom build rules (e.g., generating `.c` files from other sources).
- A mechanism for caching or saving dependency analysis to reduce overhead in subsequent builds.

=== Won't Have
- Features requiring external tools or build systems (e.g., Make, Ninja, or shell scripts).
- Automatic dependency resolution for third-party libraries (e.g., downloading or fetching dependencies).
- Support for languages other than C and C++.

== Method

To address the requirements, the single-header build system will implement the following architecture and features:

=== High-Level Architecture

The build system will consist of these core components:
1. **Source File Discovery**: Automatically scans user-defined directories for `.c` and `.cpp` files to populate a list of source files.
2. **Dependency Management**: Tracks dependencies for each source file, including:
   - File timestamps to determine if a rebuild is required.
   - Optional user-specified dependency files or headers.
3. **Build Execution**: Handles the compilation and linking process:
   - Compiles each source file into an object file (`.o`) with optional flags.
   - Links object files into executables or libraries based on user-defined targets.
4. **Configuration Interface**: Exposes a simple API in the header for users to define:
   - Source directories.
   - Targets (executables/libraries) and their dependencies.
   - Optional compilation flags and include paths.

=== Single-Header Design

The single header will contain the following:
1. **Build Configuration Macros**:
   - Macros for defining source directories, target executables, and dependencies.
   - Example:
     ```c
     #define BUILD_TARGETS \
         TARGET("app", {"main.c", "utils.c"}, {"-O2", "-Wall"})
     ```
2. **Core Functions**:
   - `discover_sources()`: Scans directories for `.c`/`.cpp` files.
   - `build_target(target_name, sources, flags)`: Compiles and links the target.
   - `should_rebuild(file, dependencies)`: Checks timestamps to determine if a rebuild is necessary.
3. **Minimal Standard Library Usage**:
   - Use standard C functions (`fopen`, `stat`, `system`) to ensure portability.

==== Source File Discovery

The build system will implement source file discovery by scanning user-defined directories for `.c` and `.cpp` files. The process includes:

1. **Directory Scanning**:
   - Recursively scan directories provided by the user for source files.
   - Detect files with extensions `.c` or `.cpp` and exclude non-source files (e.g., `.h`, `.o`, or temporary files).

2. **Portable Implementation**:
   - Use standard C functions for file and directory operations:
     - `opendir()` and `readdir()` on POSIX systems.
     - `_findfirst()` and `_findnext()` for Windows.

3. **User Configuration**:
   - Users specify directories to scan using macros or functions:
     ```c
     #define SOURCE_DIRECTORIES {"src", "lib"}
     ```
   - Defaults to the current directory (`"."`) if no directories are specified.

4. **Output**:
   - Produces a list of discovered source files to be passed to the build pipeline.
   - Example output:
     ```
     Discovered files: main.c, utils.c, module.cpp
     ```

5. **Error Handling**:
   - Gracefully handle scenarios like inaccessible directories or missing paths.
   - Provide descriptive error messages:
     ```
     Error: Cannot open directory 'src': Permission denied.
     ```

=== Implementation Details

The discovery function will have the following structure:

```c
#include <stdio.h>
#include <string.h>
#include <dirent.h>

#define MAX_FILES 1024

typedef struct {
    char *files[MAX_FILES];
    int count;
} SourceFileList;

SourceFileList discover_sources(const char *directories[], int dir_count) {
    SourceFileList list = { .count = 0 };

    for (int i = 0; i < dir_count; i++) {
        DIR *dir = opendir(directories[i]);
        if (!dir) {
            fprintf(stderr, "Error: Cannot open directory '%s'.\n", directories[i]);
            continue;
        }

        struct dirent *entry;
        while ((entry = readdir(dir)) != NULL) {
            if (entry->d_type == DT_REG &&
                (strstr(entry->d_name, ".c") || strstr(entry->d_name, ".cpp"))) {
                list.files[list.count++] = strdup(entry->d_name);
            }
        }

        closedir(dir);
    }

    return list;
}
```

==== Dependency Management

The build system will manage dependencies for each source file to ensure accurate and efficient rebuilding. Dependencies will include:
1. **The Source File**: Always tracked to detect changes to its content or timestamp.
2. **Optional User-Defined Dependencies**: Users can specify additional files, such as headers or configuration files, that should trigger a rebuild if modified.

=== Key Components

1. **File Timestamp Checking**:
   - Compare the last modified time of each source file and its dependencies against the corresponding object file.
   - If the object file is older, mark it for rebuilding.

2. **User-Defined Dependencies**:
   - Users can specify dependencies directly in the configuration:
     ```c
     #define DEPENDENCIES \
         DEP("main.c", {"main.h", "config.h"}), \
         DEP("utils.c", {"utils.h"})
     ```
   - Defaults to no additional dependencies if unspecified.

3. **Portable Implementation**:
   - Use `stat()` on POSIX systems and `_stat()` on Windows to fetch the `st_mtime` of files.

4. **Rebuild Decision**:
   - A file is marked for rebuilding if:
     - Its timestamp is newer than its corresponding object file.
     - Any user-specified dependencies have newer timestamps.
   - Example output during a build:
     ```
     Checking dependencies for main.c...
     -> Rebuild required: main.c is newer than main.o.
     ```

5. **Graceful Handling of Missing Files**:
   - Handle cases where files are missing (e.g., object files not yet created) by forcing a rebuild.

=== Implementation Details

The dependency checking function will have the following structure:

```c
#include <stdio.h>
#include <sys/stat.h>
#include <string.h>
#include <stdlib.h>

int should_rebuild(const char *source, const char *object, const char *dependencies[], int dep_count) {
    struct stat source_stat, object_stat;

    // Check if source file exists
    if (stat(source, &source_stat) != 0) {
        fprintf(stderr, "Error: Source file '%s' not found.\n", source);
        return 1;
    }

    // Check if object file exists
    if (stat(object, &object_stat) != 0) {
        return 1; // Object file missing, rebuild required
    }

    // Compare source and object file timestamps
    if (source_stat.st_mtime > object_stat.st_mtime) {
        return 1; // Source is newer, rebuild required
    }

    // Check dependencies
    for (int i = 0; i < dep_count; i++) {
        struct stat dep_stat;
        if (stat(dependencies[i], &dep_stat) != 0) {
            fprintf(stderr, "Warning: Dependency '%s' not found.\n", dependencies[i]);
            return 1; // Missing dependency, rebuild just in case
        }

        if (dep_stat.st_mtime > object_stat.st_mtime) {
            return 1; // Dependency is newer, rebuild required
        }
    }

    return 0; // No rebuild required
}
```

==== Compilation

The compilation process involves converting source files (`.c` and `.cpp`) into object files (`.o`) with optional user-defined flags. Each file will be compiled independently, enabling modular builds and minimizing rebuild times.

=== Key Components

1. **File-to-Object Mapping**:
   - Each source file maps directly to an object file.
   - Object file names will be derived from source file names, ensuring unique outputs for each target.
     Example: `main.c` -> `main.o`

2. **User-Defined Compilation Flags**:
   - Users can specify additional flags on a per-file or global basis:
     ```c
     #define COMPILATION_FLAGS \
         FLAGS("main.c", {"-O2", "-Wall"}), \
         FLAGS("*", {"-g"})
     ```
   - Defaults to no additional flags if unspecified.

3. **Portable Command Execution**:
   - Use the `system()` function to invoke the compiler (e.g., `gcc` or `clang`).
   - Example command:
     ```
     gcc -c main.c -o main.o -O2 -Wall
     ```

4. **Error Handling**:
   - Capture and display compiler output to help users debug errors.
   - Example:
     ```
     Error: Compilation failed for 'main.c'.
     Output: undefined reference to 'some_function'
     ```

5. **Parallel Compilation (Optional)**:
   - Provide an option for parallel builds to utilize multiple CPU cores, reducing build times.
   - Example using `-j` for job control:
     ```
     make -j4
     ```

=== Implementation Details

The compilation function will have the following structure:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// Helper function to build the compiler command
void build_compile_command(const char *source, const char *object, const char *flags[], int flag_count, char *command, size_t size) {
    snprintf(command, size, "gcc -c %s -o %s", source, object);

    for (int i = 0; i < flag_count; i++) {
        strncat(command, " ", size - strlen(command) - 1);
        strncat(command, flags[i], size - strlen(command) - 1);
    }
}

// Compile a single source file
int compile_source(const char *source, const char *object, const char *flags[], int flag_count) {
    char command[512];
    build_compile_command(source, object, flags, flag_count, command, sizeof(command));

    printf("Compiling: %s\n", command);

    int result = system(command);
    if (result != 0) {
        fprintf(stderr, "Error: Compilation failed for '%s'.\n", source);
        return result;
    }

    return 0; // Success
}
```

==== Linking

=== Key Components

1. **Target Configuration**:
   - Users specify targets (executables or libraries) and the object files required to build them:
     ```c
     #define BUILD_TARGETS \
         TARGET("app", {"main.o", "utils.o"}, {"-lm"}), \
         TARGET("libmylib.a", {"module1.o", "module2.o"}, {})
     ```
   - The first parameter is the target name (output file).
   - The second parameter is the list of object files.
   - The third parameter is optional linker flags (e.g., `-lm` for the math library or `-shared` for shared libraries).

2. **Linking Process**:
   - For executables:
     - Combine object files and link with optional system libraries (e.g., `-lm`).
     - Example command:
       ```
       gcc main.o utils.o -o app -lm
       ```
   - For static libraries:
     - Use `ar` to archive object files into a library.
     - Example command:
       ```
       ar rcs libmylib.a module1.o module2.o
       ```

3. **Error Handling**:
   - Display detailed errors if the linker fails (e.g., unresolved symbols).
   - Example:
     ```
     Error: Linking failed for target 'app'.
     Output: undefined reference to 'some_function'
     ```

4. **Rebuild Check**:
   - The target will be rebuilt if:
     - Any of its object files have been modified since the last build.
     - The target file does not exist.

=== Implementation Details

The linking function will have the following structure:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// Build the linker command
void build_link_command(const char *target, const char *objects[], int obj_count, const char *flags[], int flag_count, char *command, size_t size) {
    snprintf(command, size, "gcc -o %s", target);

    for (int i = 0; i < obj_count; i++) {
        strncat(command, " ", size - strlen(command) - 1);
        strncat(command, objects[i], size - strlen(command) - 1);
    }

    for (int i = 0; i < flag_count; i++) {
        strncat(command, " ", size - strlen(command) - 1);
        strncat(command, flags[i], size - strlen(command) - 1);
    }
}

// Link a target
int link_target(const char *target, const char *objects[], int obj_count, const char *flags[], int flag_count) {
    char command[512];
    build_link_command(target, objects, obj_count, flags, flag_count, command, sizeof(command));

    printf("Linking: %s\n", command);

    int result = system(command);
    if (result != 0) {
        fprintf(stderr, "Error: Linking failed for target '%s'.\n", target);
        return result;
    }

    return 0; // Success
}
```

==== Build Execution

=== Key Steps

1. **Initialization**:
   - Load user-defined configuration for:
     - Source directories.
     - Targets (executables or libraries).
     - Compilation and linker flags.
   - Initialize internal data structures to track source files, object files, and dependencies.

2. **Source File Discovery**:
   - Call `discover_sources()` to populate the list of source files.

3. **Dependency Checking**:
   - For each source file, determine whether it needs to be rebuilt using `should_rebuild()`.

4. **Compilation**:
   - Compile each source file into an object file if a rebuild is required.
   - Track compilation errors and stop the build process if any occur.

5. **Linking**:
   - For each target, check whether it needs to be rebuilt based on its object files.
   - If required, link the object files into the specified executable or library.

6. **Full Rebuild Option**:
   - If the user specifies a "force rebuild" flag, skip dependency checks and rebuild all files and targets.

=== Implementation Details

The main build function orchestrates all steps:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// Mock user configuration
#define SOURCE_DIRECTORIES {"src"}
#define BUILD_TARGETS \
    TARGET("app", {"main.o", "utils.o"}, {"-lm"})

void build_project() {
    const char *directories[] = SOURCE_DIRECTORIES;
    const int dir_count = sizeof(directories) / sizeof(directories[0]);

    // Step 1: Discover source files
    SourceFileList sources = discover_sources(directories, dir_count);
    if (sources.count == 0) {
        fprintf(stderr, "Error: No source files found.\n");
        return;
    }

    // Step 2: Dependency checking and compilation
    for (int i = 0; i < sources.count; i++) {
        const char *source = sources.files[i];
        char object[256];
        snprintf(object, sizeof(object), "%s.o", strtok(strdup(source), "."));

        if (should_rebuild(source, object, NULL, 0)) {
            const char *flags[] = {}; // Add per-file flags if needed
            if (compile_source(source, object, flags, 0) != 0) {
                fprintf(stderr, "Build failed during compilation.\n");
                return;
            }
        }
    }

    // Step 3: Linking targets
    const char *objects[] = {"main.o", "utils.o"};
    const char *flags[] = {"-lm"};
    if (link_target("app", objects, 2, flags, 1) != 0) {
        fprintf(stderr, "Build failed during linking.\n");
        return;
    }

    printf("Build completed successfully.\n");
}
```
